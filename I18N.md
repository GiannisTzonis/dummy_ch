# Translations: French, Italian, German, Spanish

Started 2026-10-12. Decisions (owner): translate **everything**, current pages first; each batch is
published once it passes the automatic checks and an independent review pass (no native-speaker
gate; review files per language can be produced for native speakers later).

## How it works

- **Addresses:** `/fr/…`, `/it/…`, `/de/…`, `/es/…`, the same page paths as `/en/` and `/el/`.
- **Source text:** English (`en`) and Greek (`el`) stay the source, generated from the legacy pages
  (`npm run legacy:import`, verbatim + recorded corrections). Translations are made **from the
  English**; names follow the English spelling (Latin script).
- **Where translations live:** a translation memory per language,
  `web/app/content/translations/<lang>/b<batch>.json`, never in the generated content files: each
  entry maps a fingerprint of one English value (a title, a label, or one paragraph/heading/list)
  to its translation. Text repeated on many pages (jury bios) is translated once; a changed English
  value gets a new fingerprint, so it shows in English until translated again.
- **Workflow:** `node scripts/i18n/pack.mjs <lang> <batch>` writes work packets (untranslated units)
  to `web/scripts/i18n/work/`; translators (brief: `web/scripts/i18n/TRANSLATOR-BRIEF.md`) write
  the matching `.out.json`; `node scripts/i18n/accept.mjs <lang> <batch>` checks each unit and adds
  the passing ones to the memory; `node scripts/i18n/status.mjs [lang batch]` shows progress.
- **Fallback:** a value with no (current) translation shows the English. A page not yet
  translated is still served at `/fr/…` with a short note in French that the page is shown in
  English; search engines are told it is the English page (`canonical` -> `/en/…`, `noindex`), and
  it is left out of the sitemap and the `hreflang` links.
- **Layout:** the festival/masterclass/competition layout recognises sections from heading words
  ("Jury", "Participating Choirs", weekdays…). Translated headings carry their English source, and
  the layout is worked out from that, so every language gets the same layout.
- **Published languages:** `web/app/content/site-locales.ts`. A language is added there only when its
  pages are ready. Local preview of an unpublished one: `VITE_PREVIEW_LOCALES=fr npm run dev`.

## Checks before a page is published

1. **Structure:** same number and kinds of blocks as the English; same images, links, anchors,
   heading levels and alignment.
2. **Facts:** the same numbers (years, dates, scores, prices, ordinals) in the same order; every
   person and choir name of the English present; capitals-only labels stay capitals.
3. **Completeness and length:** every localized value translated; length within a sane ratio of
   the English (no dropped or invented sentences).
4. **Review pass:** an independent reader compares translation and English for meaning, terms
   (choral vocabulary), tone and grammar; fixes go back through the checks.
5. The English/Greek content check (`npm run legacy:check`) stays at 0 differences.
